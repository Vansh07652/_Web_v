# Implementation Change Log

A single, continuous record of what each phase of work actually changed in the
MedMosa repository. It exists so that anyone picking the project up later can
reconstruct how the codebase reached its current state without reading the full
commit history, and so that any regression can be traced back to the phase that
introduced it. Entries describe what was done, not what was planned.

Each phase appends exactly one row to the table below when it completes. Rows are
never edited or removed after the fact; if a later phase reverses an earlier
decision, that reversal is recorded as its own row. Phases are listed in
ascending order, oldest first, so the newest entry is always at the bottom.

## Conventions

- **Phase** — the phase number and its short name.
- **Date** — the date the phase completed, `YYYY-MM-DD`.
- **Summary** — one sentence stating what the phase changed.
- **Files touched** — the files created, updated, moved, or removed. `None` when
  the phase changed no repository file. Paths are relative to the repository
  root.
- **Gates run** — the quality gates executed, with their results. Gates blocked
  by the execution environment are recorded as `blocked (environment)` and are
  never counted as failures.

Every phase report lives alongside this log in `web/_audit/`, and the row for a
phase should be read together with that phase's report.
